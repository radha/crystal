# Crystal stdlib — comparative performance opportunities vs Rust/C++/Go

Cross-language audit of Crystal's stdlib hot paths against named reference designs (Rust `memchr`/`hashbrown`/`ipnsort`/`driftsort`, Abseil/folly, Go runtime, simdjson/simdutf, serde_json, aklomp/base64, Hinnant/Neri-Schneider chrono). Tags: **(sharpens backlog)** = overlaps an existing internal item; only the new comparative detail is added. *(partial)* / *(unverified)* mark verdict confidence.

## 1. String search & scanning

Ordered by leverage; all stdlib-fixable.

- **byte_index(Int) ignores the bound memchr** — `src/string.cr:3759-3769` · scalar `upto` byte loop, 1 byte/iter · ref: glibc/musl `memchr` SWAR+SSE2/AVX2 (already wrapped by `Slice#fast_index`, `slice.cr:1228`) · delegate to `to_slice.fast_index(byte.to_u8!, offset)` · **3-10x where hit (each_line `\n` scan, null-scan over medium+ strings); marginal on the common short-string callers** · risk Low · stdlib · non-semver · *(partial: hotness narrower than claimed — `index(Char)` already memchr'd; tier down to Medium)*.
- **split(String) naive O(n·m) memcmp-per-offset** — `src/string.cr:4200/4226-4239` · full `memcmp` of the whole separator at *every* byte index, advance-by-1 — strictly worse than its own Rabin-Karp · ref: Go `strings.Split` iterates via memchr-anchored `Index`; Rust `str::split` uses `memchr::memmem` searcher iterator · anchor inner loop on `fast_index(sep[0], i)`, memcmp only the remaining bytes at hits · **1.5-5x typical (4-15x only for long rare-first-byte separators / large sparse inputs); diluted by per-piece String + Array allocation** · risk Low · stdlib · non-semver · **(sharpens backlog)**.
- **Substring search = pure Rabin-Karp, no memchr first-byte anchor** — `src/string.cr:3827 (byte_index(String))`, `:3377 (index(String))` · u32 rolling hash (multiply+add) on *every* haystack byte, memcmp only on hash hit; engine behind index/includes?/gsub(String)/scan(String) · ref: Go `bytes.Index` anchors on first byte via SSE/AVX2 `bytealg.IndexByte`, quick-checks 2nd byte, RK only after `Cutover` false positives; Rust `memmem` picks two rare needle bytes by a background-frequency table + AVX2 prefilter, Two-Way general case · scan first needle byte via `memchr`, memcmp the rest at hits, optional Go-style failure-count cutover to keep RK fallback · **High for index/byte_index/includes?/rindex (2-4x short needles, up to 3-10x moderate+ haystacks w/ uncommon first byte); lower for gsub/partition (allocate)** · risk Medium · stdlib · non-semver · **(sharpens backlog)**.
- **count(ASCII Char) decodes every codepoint via each_char** — `src/string.cr:2913→2900` · `Char::Reader`-style decode + 32-bit Char compare per char even for single-byte ASCII needle on `single_byte_optimizable?` strings · ref: Go `strings.Count` delegates single-byte sep to `bytealg.Count` (SIMD compare + popcount); Rust `bytecount` SIMD compare + horizontal add · SWAR/SIMD byte-equality-mask + popcount over `to_slice` (note `index(Char)` at `:3346` already has this exact ASCII fast path) · **3-6x on ASCII/Latin text** · risk Low · stdlib · non-semver · **(sharpens backlog)**.
- **split(Char) drives Char::Reader where memchr suffices** — `src/string.cr:4118/4132-4141` · full UTF-8 decode per char even for ASCII separator; `index(Char)` already fast-paths ASCII but `split(Char)` does not · ref: Go `strings.IndexByte` / Rust `str::split(char)` route ASCII char to byte-level `memchr` · iterate match positions via repeated `fast_index(sep.ord.to_u8!, off)` when `sep.ascii? && single_byte_optimizable?` · **1.2-2x typical (2-5x only for block form / few separators; capped by per-piece String + Array alloc)** · risk Low · stdlib · non-semver · **(sharpens backlog)** · *(partial: ASCII Reader hits cheap width-1 branch, so win is vectorization not decode-elimination)*.
- **rindex(String) reverse Rabin-Karp, no first-byte anchor** — `src/string.cr:3527-3577` · per-byte reverse rolling hash, memcmp on hit, no bulk skip · ref: Rust `memmem::rfind`/`FinderRev` backward SIMD prefilter · hand-rolled reverse SWAR/SIMD scan + memcmp (no `memrchr` is POSIX; absent on Darwin/Windows/BSD, so cannot just bind it) · **3-8x sparse matches over medium+ strings; cold API (few internal callers), constant-factor only** · risk Medium · stdlib · non-semver · *(partial: low-priority follow-on to forward search; tier Low-Medium)*.
- **starts_with?(Char) decodes first codepoint via each_char** — `src/string.cr:5331-5337` · `each_char` reader state to fetch one codepoint, vs `ends_with?(Char)` which already byte-compares · ref: Rust `str::starts_with(char)` memcmp's the char's UTF-8 encoding against the prefix · symmetric ASCII byte-compare / `char_bytes_and_bytesize` + leading memcmp · **modest absolute, very hot predicate (routing/prefix checks)** · risk Low · stdlib · non-semver · *(unverified)*.

## 2. UTF-8 validation, codepoint counting, case mapping

- **Unicode.valid? DFA lacks ASCII bulk-skip** — `src/unicode/unicode.cr:73-94` · 64×-unrolled but branch-free shift-DFA, ~1 byte/cycle, full per-byte table load even on pure-ASCII runs · ref: Lemire/Keiser simdutf `validate_utf8` (arXiv:2010.03090) short-circuits ASCII blocks via `movemask(v & 0x80)==0`; Go `utf8.ValidString` 8-byte `&0x8080…` ASCII loop · prepend SWAR `w & 0x8080…80 == 0` skip while at accepting state, fall to DFA on first high bit · **~2-4x on ASCII-heavy `valid_encoding?` (not the full 3-8x: baseline DFA already branch-free ~1 B/cyc; SWAR lands ~1-2 GB/s, not SIMD's multi-GB/s)** · risk Low · stdlib · non-semver · *(partial)*.

## 3. Hash function (Crystal::Hasher)

- **String/Bytes hash = serial 8-byte multiply-rotate funny_hash** — `src/crystal/hasher.cr:263-285/91-95/241-243` · 8 bytes/round, two 64×64→64 muls (discards high half) + two rotates + two xors · ref: **rapidhash** (wyhash successor, vendored in rurban/smhasher) / ahash-foldhash: `mum(a,b)=lo64(a*b)^hi64(a*b)` over 16 bytes/round with two lanes, full 128-bit product (Crystal has native UInt128 → one `mulx`) · 16-byte/round mum fast path, keep seeded init + funny_hash tail for <16B · **1.3-1.8x raw hash of keys ≥32B; single-digit-to-1.3x on the common short-key Hash[String] (keys <16B fall into tail; throughput diluted by probing/equality/alloc)** · risk Medium · stdlib · non-semver · *(partial: funny_hash already has 2-lane ILP, so ILP delta smaller than claimed; magnitude overstated for typical short keys)*.
- **Per-key fresh Hasher + heavy finalizer for primitive keys** — `src/object.cr:284-286`, `hasher.cr:85-86/221-223/97-106` · `Hasher.new` loads 16B seed, `number` runs `reduce_num` (incl. a 64-bit `remainder` *integer division* for Int64/UInt64) + permute + a full murmur finalizer, then truncated to 32 bits anyway · ref: fxhash `h=(h^k)*K` / Abseil int-mix — one seeded multiply, no struct/finalizer · `Hasher.mix_int(seed,value)` shortcut for `K < Number::Primitive`/Char/Enum/Symbol/Bool · **~1.1-1.3x hot-cache integer-key microbench (eliminates the div); often noise once probe-miss memory latency dominates** · risk Medium · stdlib · non-semver · **(sharpens backlog)**.
- **64→32 truncation discards the funny_hash finalizer entropy** — `src/hash.cr:990-997`, `object.cr:284-286` · `key.hash.to_u32!` then mask low bits for the slot · ref: hashbrown/Abseil SwissTable split full 64-bit: high 57 → bucket index, top 7 → control fingerprint · minimally fold `(h ^ (h>>32)).to_u32!`; ideally keep 64-bit + derive slot from high bits · **negligible-to-marginal standalone (finalizer already avalanches the low bits; no measured probe-chain effect); main value is as the SwissTable fingerprint enabler** · risk Medium · stdlib · non-semver · **(sharpens backlog)** · *(partial: HashDoS-margin framing overstated — masked bits already depend on whole key + secret seed)*.
- **No AES-NI string-hash path** — `src/crystal/hasher.cr:263-285` · single scalar body, no CPU-feature dispatch · ref: Go runtime `aeshash` (`AESENC` over seed+data, `useAeshash` selected at init), ahash/gxhash AES rounds; seed mixed into AES key preserves DoS resistance · ISA-gated AES body via `llvm.x86.aesni.aesenc`, scalar fallback · **2-4x raw short/medium key hash on AES-NI hosts only; net map throughput well under that (probing/equality/alloc dilute)** · risk High · stdlib · non-semver · *(confirmed but correctly de-prioritized below portable rapidhash, which captures most of the win without ISA gating)*.

## 4. Hash table structure (open-addressing @indices + ordered @entries)

The flagship structural item plus the cheap standalone wins. Stdlib-fixable but the big one is High-risk.

- **No SwissTable control-byte group filtering** — `src/hash.cr:399-428/520-537/1010` · scalar linear probe; every non-empty slot forces `get_index`→`get_entry` (scattered @entries deref) + 32-bit hash compare; no per-slot metadata in @indices (only empty/entry-N) · ref: hashbrown / Abseil `flat_hash_map` / Go 1.24 swiss map: split hash into h1 (position) + h2 (top-7-bit fingerprint in a contiguous control array), `_mm_movemask_epi8(_mm_cmpeq_epi8(...))` (SSE2; NEON aarch64; SWAR else) winnows 16 slots in ~4 instructions → typically 0-1 full compares/lookup · parallel control-byte array indexing the same slots (preserves insertion-order guarantee), probe groups of 16/8, LLVM vector intrinsics or SWAR fallback · **15-40% on lookup/insert/collision-heavy + large/dense tables + expensive String/struct keys (matches Go 1.24 / Abseil's measured 20-50%); NOT the 2-5x headline — Crystal's ≤0.5 load factor keeps chains short; ≤16-entry tables already metadata-free linear scan** · risk High · stdlib · non-semver · **(sharpens backlog)** · *(partial)*.
- **Backward-shift deletion re-probes the whole cluster** — `src/hash.cr:782-809` · Knuth backward-shift: per occupied slot after the hole, `get_entry` deref + `fit_in_indices(entry.hash)` re-fit + conditional shift; O(cluster) @entries loads per delete · ref: hashbrown/Abseil/Go-1.24 write a DELETED tombstone (EMPTY if group never full), no shifting; bulk-reclaim at resize — which Crystal **already has** via `@deleted_count`/`do_compaction` · tombstone control-byte write reusing existing compaction · **O(cluster)→O(1) on delete-heavy + collision-heavy (churny/LRU caches); typical no-collision delete already near-O(1)** · risk Medium · stdlib · non-semver · *(confirmed; not standalone — needs a DELETED sentinel distinct from EMPTY, so couples with control bytes)*.
- **Raise max load factor 0.5→~0.875** — `src/hash.cr:984-987/913-915` · `entries_capacity = indices_size//2`; @indices kept ≥2× @entries; resize fires at 50% · ref: Abseil/hashbrown 0.875, Go 1.24 7/8, folly F14 ~0.857 (high load tolerable *because* SIMD control filtering keeps chains cheap) · couple with control bytes, set `entries_capacity = indices_size*7//8` · **fewer O(n) resizes is real; but the "~2x memory" claim applies only to the SMALLEST buffer (@indices is 1-4 B/slot vs ~24 B/@entries slot) → only a few % of total Hash memory, not 2x. Standalone (no control bytes) lengthens chains exactly as the design comment warns** · risk Medium · stdlib · non-semver · *(partial: Datadog's "hundreds of GB" came from the full SwissTable redesign, not a load-factor tweak)*.
- **64→32 hash truncation blocks a high-bit fingerprint** — `src/hash.cr:990-997/1008/1010` · `to_u32!`, Entry stores `@hash:UInt32`, the only pre-key filter (needs an @entries load to check) · ref: SwissTable carves h2 from the top 7 bits · keep UInt64 or a separate UInt8 fingerprint pre-truncation · **minor standalone (for typical table sizes the current UInt32 still has ≥7 free high bits above the mask, so a fingerprint is derivable without widening); meaningful only as the finding-#1 enabler** · risk Low · stdlib · non-semver · **(sharpens backlog)** · *(partial)*.
- **Per-probe 3-way branch on @indices_bytesize** — `src/hash.cr:750-764/766-780` · `case @indices_bytesize when 1/2/else` re-tested on every probe step (invariant for the table's lifetime; only differs at >256 / >65536 entries) · ref: hashbrown/Abseil/Go fixed branch-free stride; Rust monomorphizes the probe over integer width · hoist into 3 macro-generated `probe_u8/u16/u32` variants, dispatch once · **low single-digit % at best (branch is perfectly predicted; per-step time dominated by the @entries cache-miss load + key compare); clean refactor, helps vectorizable build/compaction loops** · risk Low · stdlib · non-semver · **(sharpens backlog)** · *(partial: not "low-double-digit %")*.
- **fit_in_indices recomputes `(1<<pow2)-1` per call** — `src/hash.cr:946-953/941-944` · derives the mask from the stored log on every probe step · ref: hashbrown/Abseil/Go cache `bucket_mask`, `(pos+stride)&mask` · add cached `@indices_mask`, updated only on resize · **small pure win per probe step** · risk Low · stdlib · non-semver · *(unverified)*.

## 5. Sorting & selection

- **min(count)/max(count) run quickselect once per output element — Θ(count·n)** — `src/enumerable.cr:1118/1231/1056/1071` · `(0...count).map { quickselect_internal(data,0,n-1,…) }` — each call restarts left=0,right=n-1, fresh O(n) first partition; Lomuto inner loop branchy + bounds-checked via `Array#[]` · ref: C++ `partial_sort`/`nth_element` introselect O(n+k log k); Rust `select_nth_unstable` O(n) then sort prefix; Go bounded max-heap O(n log count) · one `quickselect_internal(…, n-count)` then `unstable_sort!` the count-tail (or size-count heap when count≪n) · **O(count·n)→O(n+count log count): ~50-100x for top-k where k~n/2; negligible for k=1** · risk Low · stdlib · non-semver. **← highest-leverage, lowest-risk sort item.**
- **Unstable intro_sort! = branchy Hoare + median-of-3, depth-only fallback** — `src/slice/sort.cr:8/52/71` · textbook Hoare scan (branch mispredict/element on random data), no pattern detection before the heap-sort depth limit fires · ref: Rust **ipnsort** (`sort_unstable`) & Go/orlp **pdqsort** (arXiv:2106.05123): BlockQuicksort branchless block partition (offset buffer `offsets[num]=i; num+=pred(elem)` + cyclic swaps), ninther pivot for large n, `partial_insertion_sort` already-partitioned short-circuit, bad-partition shuffle + `BAD_ALLOWED=log2(n)` → heapsort · rewrite `partition_for_quick_sort!` branchless, ninther, pdqsort fallback; keep `heap_sort!` as the O(n log n) guarantee · **2-2.4x random primitives (Int `<=>` inlines branchless; plain `sort!` routes primitives here too), up to 10x+ on adversarial/low-cardinality; less for block/sort_by (closure dilutes)** · risk Medium · stdlib · non-semver.
- **Stable merge_sort! = pre-driftsort TimSort with Array(Range) run stack** — `src/slice/sort.cr:257/278-314/552` · ports the 2020 rustc TimSort; run stack is heap `Array(Range)` with per-run boxing + `runs.delete_at` (O(run-count) shift per merge) · ref: Rust **driftsort** (1.81, Sept 2024, from glidesort): stable quick/merge hybrid, run detection, powersort near-optimal merge order, branchless stable sort4 small-sort; ~17x on low-cardinality `random_d20`, >2x random vs the TimSort it replaced · **Tier (b) algorithm swap is the real multi-x win (esp. many-equal-keys); Tier (a) run-stack cleanup is overstated — TimSort bounds the stack to O(log n)≈49, so delete_at shifts + Range allocs are O(log n), dominated by O(n log n) merge work → low-single-digit % at best** · risk Medium · stdlib · non-semver.
- **Small-array base case = branchy insertion sort** — `src/slice/sort.cr:5/87/240/322` · quicksort leaves (≤16) finished by one branchy insertion `shift` loop (+ per-cmp nil-check); merge runs ≤10 via `insert_head!`; no sorting networks · ref: Rust ipnsort branchless sort4/sort8 (`cmp_swap`→cmov, `SMALL_SORT_NETWORK_THRESHOLD=32`); DeepMind **AlphaDev** (Nature 2023) sort3/4/5 assembly networks in libc++ · branchless min/max compare-exchange networks for n∈2..8, keep insertion for 9..16 · **5-20% on random primitive-keyed slices (direct `<` cmov feasible); near-zero for block-comparator / non-primitive sort_by (the `<=>`+nil-check `cmp` doesn't lower to clean cmov)** · risk Medium · stdlib · non-semver.
- **Indexable::Mutable#sort! gathers into a temp Slice and scatters back** — `src/indexable/mutable.cr:336/359/387/419` vs `array.cr:1691` (Array sorts `@buffer` in place via `to_unsafe_slice`) · extra n-element alloc + two element-wise copies for non-Array contiguous mutables (StaticArray, user types) · ref: Rust `[T]::sort`/C++ `std::sort(begin,end)` operate in place (stable allocates only the n/2 merge buffer) · sort in place over the contiguous pointer where exposed; bulk `copy_from` scatter-back otherwise · **removes 1 alloc + 2 copies/sort for those types** · risk Low · stdlib · non-semver · *(unverified)*.

# Biggest structural gaps (algorithm-level rewrites)

1. **SwissTable Hash (control-byte SIMD group probing)** — port hashbrown / Abseil `flat_hash_map` / Go-1.24 swiss map: parallel 1-byte control array of 7-bit h2 fingerprints + EMPTY/DELETED sentinels, `movemask(cmpeq)` over 16 slots (SSE2 / NEON / SWAR). Keep `@indices→@entries` indirection to preserve insertion order. Unlocks: 15-40% lookup/insert throughput, O(1) tombstone deletion (reusing existing `do_compaction`), and 0.5→~0.875 load factor. **Prereqs in backlog: stop the 64→32 truncation (carve h2 from the high bits), hoist the @indices_bytesize branch.** High risk, but the single largest structural payoff. *(realistic 1.2-1.4x throughput, not 2-5x, given Crystal's already-low load factor.)*

2. **pdqsort / ipnsort unstable sort** — replace branchy Hoare partition with BlockQuicksort branchless block partitioning (offset buffer + cyclic swaps), ninther pivot, `partial_insertion_sort` short-circuit, bad-partition shuffle + `BAD_ALLOWED=log2(n)`→heapsort. Add branchless sort4/sort8 networks for the n≤8 leaves. Payoff: **2-2.4x random primitive sort, up to 10x+ adversarial** (`sort!` routes primitives here). Medium risk, pure `src/slice/sort.cr`.

3. **driftsort stable sort** — port Rust 1.81's stable quick/merge hybrid (powersort merge order + branchless small-sort), replacing the pre-driftsort TimSort. Payoff: **up to ~17x on low-cardinality (`random_d20`), >2x random**. Medium risk. (The Array(Range) run-stack cleanup alone is low-single-digit % — the win is the algorithm, not the data structure.)

4. **memchr/two-way substring search** — replace Rabin-Karp (`string.cr:3827/3377`) and the naive `split(String)` loop with Rust `memchr::memmem` (rare-byte AVX2/NEON prefilter + Two-Way) or bind `LibC.memmem`. Payoff: **4-10x on index/byte_index/includes?/rindex over large sparse haystacks**, drives gsub/scan/include?/split. Medium risk. (Backlog item; sharpened with the concrete reference design.)

5. **SIMD UTF-8 validation + codepoint count** — port simdutf / Lemire–Keiser `validate_utf8` (vpshufb classification, ASCII block short-circuit) for `Unicode.valid?`, and `core::str::count` SWAR for `String#size`. Payoff: SWAR ~2-4x near-term on ASCII-heavy validate + 5-10x on cold size; full SIMD ~10-20x. Needs the intrinsics-surface enabler for the SIMD ceiling; SWAR portions are Low risk and shippable now.

6. **SIMD Base64 (+ hex) codec** — port Muła–Lemire / aklomp `vpshufb` codec (12/32 bytes/round, branchless alphabet map). Payoff: **~7-10x bulk encode/decode**. Gated on the **vector-intrinsics surface** (`src/intrinsics.cr` binds only scalar ops, and `fun` cannot natively spell LLVM vector types → real codegen work + CPUID dispatch, not "one piece of plumbing"). Portable SWAR fallback (~2-3x) ships without it.

# Confirmed already best-in-class — do not churn

Validated by the cross-language comparison; no gap found:

- **Float→string = Dragonbox** (state of the art).
- **String→Float (`to_f`/`to_f64`) = fast_float / Eisel–Lemire** (`Float::FastFloat`) — already best-in-class.
- **BigInt = GMP**; **Int#gcd = binary/Stein** with intrinsics; **String→Int = wrapping ops + lookup table**.
- **Int#to_s base-10 two-digit table** (committed); **Time pad2/pad4 two-digit table** (already on this branch).
- **Bit ops** (popcount/clz/ctz/bswap/rotate) → LLVM intrinsics; **Math.sqrt = hardware `sqrtsd`**; **Float64\*\*(Int32) = `powi`**.
- **Non-throwing exception path is zero-cost** (table LSDA); **x86-64 fiber `swapcontext` asm is minimal**.
- **Case-range tables are already sorted/contiguous/inline-packed** (12 B/entry, no pointer-chase) — only the lazy-init Array allocation is worth removing, NOT the search structure.
- **JSON::Builder already run-batches verbatim runs** via `write_string` — only the per-byte classifier (item #10.3) is the gap.

**Structural blockers (out of stdlib scope — compiler/runtime work):** conservative non-moving Boehm GC + every class heap-allocated; no escape analysis / stack allocation; integer-overflow checks on by default; IO abstract read/write virtual dispatch. These cap several findings above (e.g. the Array SBO ceiling, each_char block-yield floor) and cannot be fixed in stdlib alone.
